# The archive carries what the manifest covers, and nothing else

## Goal

让**归档交付的集合**与**清单描述的集合**是**同一个** ✓ —— 今天不是 ✓：`sourceDigest` 刻意跳过 `__pycache__` ✓，而归档里带着 **17 个 `.pyc`** ✓，每个都内嵌**构建机的绝对路径** ✓。

**用户价值** ✓：清单是"这个构建是什么"的**声明** ✓；一个描述范围**小于**交付范围的声明 ✓，正是本仓反复在找的那类缺陷 ✓ —— 而且这次它把一个**构建机路径**送进了每个用户的下载里 ✓。

## Background（由验证者实测 ✓，2026-10-16）

- **v0.2.4 的归档里有 17 个 `.pyc`** ✓，其中包括 `installer/__pycache__/layout.cpython-311.pyc` ✓ —— 原始字节里能直接读出 `D:\a\dove-pi\dove-pi\installer\…` ✓✓（AI 构建机上的路径 ✓）。
- **`release:check` 带着它们照样通过** ✓ ⇒ 检查与装配两处**对"归档该有什么"没有共同的定义** ✓。
- **不是本轮引入** ✓：v0.2.3 的归档同样带 17 个 ✓（v0.2.3 → v0.2.4 的差集只有一个文件 ✓）。
- **泄漏机制本仓早已记录** ✓：一个副本里的 `__pycache__` 让 agent 学到了源克隆的绝对路径 ✓（`personal-agent-field-run.md` 的"副本不是围栏"一条 ✓）—— 同一个机制 ✓，这次是**发出去**而不是留在本机 ✓。
- **include 清单 18 项全部存在** ✓ 且根层解包无多余套层 ✓ ⇒ 问题只在**清单外多出来的东西** ✗。

## Requirements

- **R1 归档里不得有缓存** ✓：`__pycache__` 与 `*.pyc` ✓（以及本仓已在别处命名过的那些缓存目录 ✓）不得进入发布归档 ✓。
- **R2 让两处**不可能**再不一致** ✓：`release:check` 必须**拒绝**含缓存的归档 ✓ —— 这样"装配"与"检查"对同一件事有同一个定义 ✓，而如果只改了装配 ✗，CI 会**响亮地失败** ✓（这是想要的耦合 ✓）。
- **R3 同一规则只写一次** ✓：排除规则与拒绝规则来自**同一处定义** ✓，不在 workflow 与本地重演里各写一份 ✓。
- **R4 先红后绿** ✓：一条**今天必红**的用例 ✓ —— 让 readiness 检查面对一个含 `.pyc` 的归档 ✓，它必须拒绝 ✓。
- **R5 不改交付内容本身** ✓：**不**因为顺手而改 include 清单的构成 ✓（除了缓存 ✓），也不动 manifest 的摘要算法 ✓。

## Acceptance Criteria

- [ ] 一条**今天必红**的用例 ✓：把 `release:check` 指向一个**含 `__pycache__` 的归档** ✓，它必须**拒绝**并指名那个路径 ✓。
- [ ] 装配侧（workflow ✓）与本地重演 ✓ 都不再把缓存放进归档 ✓，且两者的排除来自**同一处定义** ✓。
- [ ] **重造一次归档**并确认：17 → **0** ✓；其余 344 个文件与 `git archive <tag>` **逐字节相同** ✓（用验证者用过的那条判据 ✓）。
- [ ] `release:check` 在**清干净**的归档上仍通过 ✓，且 `sourceDigest` 覆盖的范围与归档交付的范围**现在相同** ✓（或差异被明说 ✓）。
- [ ] 四门与 `npm test` 全绿 ✓；`document-drift` 能解析新规则行的执行器 ✓。

## Out of Scope

- **发布的密码学来源证明** ✗ —— 验证者另记了一条：`isImmutable: false` ✓、校验和与归档来自**同一**信任源 ✓ ⇒ 能防传输损坏 ✓、防不了发布被换掉 ✓。那是另一件事 ✓（需要签名或 attestation ✓），不塞进这里 ✓。
- **39 条 profile 映射逐条核对** ✗ —— 验证者只验了条数与抽查 ✓；那是**另一个**核对动作 ✓，不是本缺陷 ✓。
- **在干净机器上真跑一遍 `install.ps1`** ✗ —— 验证者验的是**静态契合** ✓；真装一遍属于读数那个子任务 ✓。
- **已发布的 v0.2.3 / v0.2.4 归档** ✗ —— 已发布的字节不动 ✓（发布如何被取代，是父任务地图上的事 ✓）。
