# A3 设计：事件模型、通道、以及保真度那一格（无先例）

## 边界

本任务实现 §2.4 的 trace 通道与 §2.3 的配置保护。**三性质缺一不可**：完整性、保真度、捕获。

## 决策 1：事件模型 → **类型化事件 + 到证据支撑关系的投影**（照综述 `2606.04990`）

- 每个事件绑定**八个语义字段**（照 Agent Flight Recorder：从意图 → 执行 → 来源）。
- 事件的存储形态是**类型化图**；对外的"证据"是它到**证据支撑关系**上的投影。
- 分类轴按其建议设计：trace 来源、证据/执行单元、来源关系、**粒度与时机**、表示形式、**trust functions**。

**为什么照它**：它给了词汇，axi 不必自造；而且"粒度与时机"这一轴正好覆盖 A2 的跨调用状态。

## 决策 2：通道 → **宿主外拦截**

- **记录点在 loop 内、工具执行前后**（这样才有"捕获"），但**写入端不在 agent 的宿主里**：独立进程 / 独立路径，agent 既不能写也不能删。
- 写入是 **append-only**，**另记重试与完成状态**（原文要求：*"records must be append-only, with retries and completion statuses recorded separately"*）。
- **抗定时清理**：写入不可由 agent 触发；即使 agent 反复尝试延迟/重复清理（实测出现过），也不影响已写记录。

## 决策 3：完整性 → **本地锚点即可**，不必上链

采用 hash chaining + Merkle batching，**epoch root 定期写到一个 agent 写不到的位置**作为锚点。

**第一版不上链**：链上锚定的价值是"**无需事先约定可信中介的第三方校验**"，而那在单机自我改进的第一版里用不上。**但要把性质写清**：锚点必须**可被外部独立校验**（只要有载荷与包含证明），这样将来要换到链上时只是换个落点，不用改结构。

**成本已有实测**（可引用，反驳"太贵"）：每事件 ~48 µs / 512 B；L2 锚定 $2.30 / 10 万事件。

## 决策 4：保真度 → **执行回执对账（没有先例，本任务是原创新）**

**这一格不能靠 hash 链解决。** Agent Flight Recorder 检出的四类是 edit / delete / reorder / fork，**不含"编造"**；而实测约 **7%** 的 transcript 存在成功的工具调用伪造，目的是欺骗自动评分器。

设计：**工具调用必须留下一个"被执行者之外产生"的回执**，并与工具自己声明的结果**对账**：

- 回执来源：执行层（A2 的隔离层 / 进程退出码 / 产物哈希 / 文件系统观测），**不是模型的叙述**；
- 对账：记录里声明的调用 ↔ 回执里的实际执行，**不一致即视为伪造**；
- **关键性质**：让伪造**要求改动 agent 写不到的东西**——这正是"独立性"的具体含义，而不只是"分开存储"。

**诚实定界**：本任务只承诺**能检测到**（对账不一致可发现），**不承诺**"不可能被绕过"。宿主被完全攻陷时，重放类审计不成立（`2609.30266` 的负面结论），这一条要写进限制声明。

## 配置保护（§2.3 的落地）

- 安全敏感参数改动需**独立批准**；参照 `ConfigChange` 钩子可否决变更。
- **仓库设置不得放宽隔离**（照 Claude Code 的一条硬规则）。
- **"让模型知道这是危险的"不算防护**（HarnessRisk：配置是最脆弱的阶段，且风险识别不等于安全行动）。

## 必须写进限制声明的三条

1. trace 记录的是**模型轨迹**，**不捕获环境状态**；
2. **不记录全部系统活动**；
3. **重放不能作为完整性的替代**（宿主被攻陷时不成立）。

## 风险

- **保真度那一格最可能做不实** → 宁可把承诺降到"可检测"，也不要写成"不可绕过"。
- **锚点被顺手写进 workspace** → 那就等于没有锚点；锚点位置必须由测试看住。
