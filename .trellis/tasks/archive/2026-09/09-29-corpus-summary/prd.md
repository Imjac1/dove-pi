# The corpus summary and the sentence it must not say

## Goal

Hold the four items of the harness loop required-test list, beginning with the negative claim about a message.

## Background: a claim about what must not be said

The list has four items and one is partly held - the reference-naming half of the failure-record item. **The sharpest remaining item is a
negative claim about a message**: the corpus summary counts each terminal class with the axis rule, splits a composite refusal label, and *says
why a corpus with no failure has none - and does not say it when the corpus holds one*.

**A claim about a sentence that must not be produced is a claim a test can hold exactly**, and the method that has worked ten times is to find
the function first and ask for its name.

## Requirements

- **R1 - Ask the file list first**, and name the candidate owners before reading them.
- **R2 - Find the summary function**, and read what it says about a corpus with no failure.
- **R3 - Hold the four items**, each against a case or an assertion.
- **R4 - Name any item not held**, and what was searched.
- **R5 - The gate passes**: typecheck, the suite, the installer tests and the spec budget test.

## Acceptance Criteria

- [x] **AC1** Candidate owners are named before their contents are read.
- [x] **AC2** The summary function is found and what it says about an empty corpus is read.
- [x] **AC3** Each of the four items is held or named.
- [x] **AC4** No item is called unheld on a single failed pattern.
- [x] **AC5** The gate passes.

## Out of scope

- **The request-runtime lists**, which stay as named.
- **Changing any behaviour.**
- **The first real turn**, which needs a Pi host.
