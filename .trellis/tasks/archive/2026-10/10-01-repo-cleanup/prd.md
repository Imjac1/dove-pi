# 清理项目里的无用之物

把仓里**真的无用**的东西找出来，**有据地**删除：可再生成的产物、已被取代的副本、以及任何"没人到达也没有理由留下"的东西。**不碰记录类与产品代码**（除非另有理由）。

用户原话：「规划把项目里面无用的东西全部删除」。

**不做**：git 历史清理、`node_modules`、归档任务、journal、任何读数、任何产品代码。

## Requirements

- **R1 只删有证据的**：每一处删除都要能说出"为什么无用"，并**指出它的替代**（可从 git 历史取回 / 可再生成 / 已被取代）。
- **R2 不碰记录类**：任务工件、读数、journal、归档、规格一律保留（除非它本身是重复副本）。
- **R3 不碰产品代码**：`src/**` 的删除必须另有理由（排期内的接线不删；有测试消费者的不删）。
- **R4 删除可复核**：提交信息里点名路径 + 依据；删除后三条门禁不下降。
- **R5 能修就修**：乱码这类"看起来是垃圾其实是被损坏的记录"，修成可读，不删。
- **R6 先证后删**：声明"已被取代/重复/在 git 里也有"之前必须先证明；证明写进提交信息或归档。

## Acceptance Criteria

- **AC-1** 三条门禁在清理后**不下降**：`npm run typecheck` 0 · `npm test` **822 / 820 pass / 0 fail / 2 skipped** · `npm run test:installer` **141 OK**。
- **AC-2** 每一条删除都能在提交历史里找到理由（提交信息点名路径 + 依据）。
- **AC-3** 清理后**不再有"两个竞争的计划正本"**：v7 `plan.md` 已删，且**全仓没有任何引用指向已删的它**（`grep 'plan\.md'` 逐条可解释）。
- **AC-4** 删除的体量有**前后原始读数**（不是"C 盘大了"这种说法）。
- **AC-5**（**新增**）备份删除前，其**在 git 历史里找不到的内容**已归档进本仓并提交，归档里含**哈希清单**（任何人事后都能核对删掉的是什么）。

## Out of Scope

- 不重构、不改产品行为、不动测试的断言。
- **不做 git 历史清理**（`filter-repo` / 重写历史）——历史是记录。
- 不删 `node_modules`（删了门禁就跑不起来，那不是"无用"）。
- 不删归档任务、journal、任何读数。
- 不碰规格（`.trellis/spec/**`）与 `harness-surface.yaml` 的声明——它们有索引检查看着，且本次扫描没有发现游离或未收录的规格。
- 不碰十六个"没人到达"的模块：它们各有记录的理由，且多数在程序排期内（这条是本次扫描的**结论**，不是遗留）。
