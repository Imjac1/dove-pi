# 第三轮：延续的读数（2026-10-05）

**方法更正先说**：10-03 那个草稿克隆**已经不存在**（`D:\aixi` 整个没了）⇒ 不用它。改用**本仓自己的仪器**：黑盒脚本 `scripts/real-dove-blackbox.mjs`（`--launcher source --provider real`，本机没有托管安装）＋**直接跑宿主**。被探项目是新建的最小项目（`C:\Users\Macfy\Desktop\dsh\continuation-probe`：一个 `sum` 函数 + 一条用例 + 一次初始提交）。第一跑要做的事：**加一个 `max(a,b)`、加覆盖两分支的用例、跑 `npm test`、提交**——因为第二跑要问的东西必须是可查真的。

## 三种情形，正好构成对照

| 跑 | 仪器 | 问的话 | 结果 | 耗时/退出 |
|---|---|---|---|---|
| **A** | 黑盒，`--provider real` | 做那件活 | 加了 `max(a,b)`、用例覆盖两分支、`npm test` 两条通过、提交 **`5f2370b`**（它自己交代的） | 138 s / exit 0 |
| **B** | 黑盒，**新会话**（不放宽任何东西） | "上一次我们做到哪了？" | **"不确定。我没有找到任何能回答这四件事的记录，所以不猜"** —— 它读了工作区，只说看得到 `sum`，并报 `taskCount: 0`、`continuation: "none"` | 65 s / exit 0 |
| **B2** | 黑盒，**仓库的 `--reuse-session` + 同一个 `--session-dir`** | 同一句话 | **同样是"不确定，我不猜"**。它甚至读到工作区里那两份**互相矛盾**的日志（一份说 `019a955`、一份说 `5f2370b`），据此判断"这些是并行评估的残留，不是连续记忆" | 236 s / exit 0 |
| **C** | **宿主的 `--session <A 的会话文件>`**，同一个工作区 | 同一句话 | **"上次我在 `index.js` 里新增了 `max(a, b)` 函数，`npm test` 两条用例全部通过（pass 2 / fail 0），提交号是 `5f2370b`。"** —— 对照 A 的交代**逐项说中**（函数 ✔ 计数 ✔ **提交号 ✔**） | **15 s** / exit 0 |

## 判据（R2）的结论：**说中**

三种情形各出一个答案，且都对：**新会话**与**共享会话根**都**明说不知道**（不是猜——而这正是判据允许的另一半）；**续上对话**的那一次**说中**，含真实提交号。⇒ **延续成立**。

## 但"哪个东西让它成立"是个真读数，不是细节

- B2 的 `sessionDir` **两次完全相同**（`...\.sessions2`），**与本仓用例断言的条件一致**（`tests/real-dove-blackbox.test.ts:543` 断言的就是"两次 `sessionDir` 相等"＋"第二跑不是第一跑的 redelivery"，由 `faux` 守着）。**而对话并没有被带过去**：根里出现了**两个**会话文件，模型没有任何记忆。
- C 用的**不是**黑盒，是宿主自己的 `--session <文件>`（宿主 `--help` 里 `--continue, -c  Continue previous session`、`--resume`、`--session <path|id>` 三个都有）。
- ⇒ **同一条判据下，"续上对话"这件事只在宿主那条路上成立。** **未隔离**的是黑盒没带过去的原因（Pi 的 RPC 模式语义 vs 黑盒构造的参数）——只知事实，不猜原因。

## 顺带量到一处**措辞比它覆盖的强**（本仓那一类缺陷）

README:415："`--reuse-session` 配合同一个 `--session-dir` 时，第二次运行**会继续第一次的会话**，而不是各拿一个 session 根目录"。
实测：**后半句成立**（确实共享同一个会话根），**前半句不成立**（对话没有继续）。`resume-across-runs` 夹具的描述写的是"a user comes back to a session in a second run and continues it"，同样比黑盒的实际行为强。
