# A3 执行清单

## 顺序

1. [ ] **写完三条限制声明**（不捕获环境状态 / 不记录全部系统活动 / 重放不能替代完整性）——先写它，避免后面顺手宣称过多。
2. [ ] **事件模型**：八个语义字段 + 类型化图的存储形态；写一条"事件可投影为证据关系"的测试。
3. [ ] **写入端与 agent 的宿主分离**：独立进程 / 独立路径；写一条测试：**agent 路径下无法删记录**。
4. [ ] **append-only + 重试与完成状态另记**；写一条测试：记录了重试与状态。
5. [ ] **hash chaining + Merkle batching**；写一条测试：改一个事件 → 链校验失败。
6. [ ] **epoch root 锚点**写到 agent 写不到的位置；写一条测试：**锚点路径不在 workspace 内**。
7. [ ] **执行回执对账（保真度）**：从执行层取退出码 / 产物哈希等回执，与声明的调用对账；写一条测试：**伪造一条未执行的工具调用 → 对账失败**。
8. [ ] **抗定时清理**：让 agent 反复尝试延迟/重复清理，已有记录不受影响；写一条测试。
9. [ ] **配置保护**：安全敏感参数改动需独立批准；仓库设置不得放宽隔离；各写一条测试。
10. [ ] **压缩路径不得改写证据**：写一条测试（压缩前后记录校验和不变）。

## 验证

- `npm run typecheck` / `npm test` 数字不下降
- 对账测试用 **METR/Redwood 的 7% 失败模式** 构造（声明的命令 ≠ 实际执行）
- 锚点路径测试必须**断言路径本身**，不只是"写成功"

## 风险点与回退

- **风险**：把"分开存储"当成"独立性" → 保真度会名存实亡。回退：把判据改成"**伪造要求改动 agent 写不到的东西**"，并逐条检查。
- **风险**：锚点被写进 workspace → 回退：把锚点位置改为配置项 + 测试看住。
- **风险**：宣称"不可绕过" → 回退：降为"可检测"，写进限制声明。
- **回退点**：保真度（第 7 步）与其余八步**解耦**；若做不实，交付其余部分并**如实标注保真度未达成**。

## 提交前

- [ ] 三条限制声明在文档里可见
- [ ] 锚点、写入端、对账回执三者的位置都**由测试看住**，不是靠注释约定
- [ ] 保真度的承诺强度与实际能力一致（可检测 ≠ 不可绕过）
