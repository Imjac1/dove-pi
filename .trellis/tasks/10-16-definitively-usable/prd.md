# Definitively usable: a gate that can be trusted, a reading taken on the tree that ships, and the release that carries it

## Goal

把"可以使用"从**一种说法**变成**一份带读数的结论** ✓。今天它由三件事夹在中间 ✓，每一件都可测 ✓：

1. **门不可信** ✗ —— CI 在慢机器上会为一个与改动无关的原因变红 ✓（本会话实测 ✓，机制已定位 ✓）；
2. **读数不是在要发的树上取的** ✗ —— 三遍客户路径跑在改动**之前** ✓，而当前 master 上有四笔未发货的产品代码 ✓；
3. **发布物落后** ✗ —— 用户今天装到的 v0.2.3 里**没有**那四笔 ✓。

用户价值 ✓：你可以对任何一个问"这东西能用吗"的人说"能"，并把这句结论**指给一组可复算的读数** ✓，而不是指给一次记忆 ✓。

## Requirements

- **R1 门必须可信**：仓库自己跑的验证**不得依赖挂钟运气** ✓ ⇒ 那条 600 ms 围栏改成让"飞行中"成为**测试自己持有的状态** ✓（子进程已经在写 stdout ✓，就让测试**等它的开始信号** ✓），而不是它祈祷出来的一段时间 ✗；并对同类的**空测试**形状一并处置 ✓。
- **R2 同类不得再生**：审计必须留下一个**执行器** ✓（规则行 + 能抓住它的判据 ✓），否则下一处还会长出来 ✓。
- **R3 读数取在要发的树上**：端到端客户路径必须在**当前 master**（含四笔改动）上重跑一遍 ✓，用**同一套判分**（副本套件 ✓ + 两个字节数 ✓）。
- **R4 发布物必须含读数所说的一切** ✓：0.2.4 ✓ 按发布作业自己的顺序验证 ✓ 再发 ✓。
- **R5 边界照旧明说** ✓：结论覆盖的范围就是**测过的范围** ✓，不因为一句话好听而外扩 ✓。
