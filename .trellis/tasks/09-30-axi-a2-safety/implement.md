## 剩余顺序（每片一条提交，可独立 revert）

### 1. 历史无关 —— ✅ **已完成（提交 `9ac178a`，证明片）**

**判据**：*"retry until relevant context leaves the monitor's history"*（§1.3 第三种手法）不得成立。

**取证已经做完**，结论是这条性质**今天成立**：

- 状态（phase 计数、per-limit 的和）活在**策略实例**里，策略只在**模式加载**时重建（`activeActionPolicy = undefined` → `createActionPolicy`）；
- `session_before_compact` 钩子**只**在"重试 + 非幂等效果已开始"时**取消**压缩，它不写策略、不写账本、不重置任何东西；
- 所以判定读的是 `(invocation, 会话状态)`，**与消息历史无关**。

**这一片要产出的是一条能抓住回归的测试**（写在那里，将来谁把状态挪回上下文、或让压缩路径碰证据，就会红）：

- 走 `tests/host-work-mode.test.ts` 已有的 host 夹具（它已经能取 `host.events.get("session_start")`）：① 花掉一次会话上限 → ② 触发 `session_before_compact` → ③ **同一次调用仍然被拒**；
- 同时断言**证据没被改**：压缩前后账本文件**逐字节相同**；
- **效用臂**：新会话是干净的（这是有意的语义，不是漏洞）。

**必须同时写清的边界（已量、未修）**：`resume` / `fork` / `reload` 会**重建策略**，于是**会话上限重置**。这是"状态按会话"的另一面：把它变成跨会话持久会**约束合法的后续工作**，而且账本今天不记录受限参数值（要种就得新增记录种类 = 改词汇）。**结论先写在这里**：按会话保持，边界如实标注；不要用"历史上出现过什么"去补它——那正是这一片要挡的东西。

### 2. 语法解析（部件 ①）

`src/core/argument-syntax.ts`：分词 + 子命令识别 + **arity/子命令表**。**表才是工作量**（语料里 ~130 条），解析器可后换。

**它要关掉的是**：`excluded_techniques` 今天只从**声明字段** `technique` 读——**字段可以不填**，于是"用等价写法做出被禁技巧"检测不到。

**这一片的红测试**：同一意图、**不填 `technique` 字段**、用别种写法表达 → 必须仍被拦；**效用臂**：同一意图的安全写法仍然通过（否则就是把可用性当安全）。

### 3. 保持性传感器（部件 ④）

`src/core/declaration-preservation.ts`：**声明 → 消费端登记 → 回合末检查**。问的是"**这条声明是否仍然管住这一轮**"，不是"是否存在"。

**红测试**：把一条声明的消费端拆掉 → 传感器**必须报警**（这条天然会红：今天没有任何东西做这件事）。

### 4. 7-mutation 故障注入（AC-3）

照参考实现的 `eval:fault-injection`：**逐条打断契约**，确认**对应**校验器报警——验证的是"契约与校验器的对应关系"本身，不是"有个校验器报警就算过"。

**它同时是覆盖率的度量**：arity 表永远不全，用注入量覆盖，不是声称覆盖。
