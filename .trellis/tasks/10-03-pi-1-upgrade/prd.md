# Pi 1.0 upgrade and the in-Pi experience

## Goal

把宿主钉点升到 **1.0.0** ✓，**让门禁说出哪里坏了** ✓，**只修真的坏了的** ✓，然后把扩展装进 Pi 并**在 Pi 里把三个已发布模式走一遍** ✓（你选的体验形态 (c) ✓）。

**用户价值** ✓：你要的是**能体验的成品** ✓ —— 而这次升级本身既是"最新基座上的成品" ✓ 的**前提** ✓，也是本项目自 09-30 以来**第一次真的动宿主版本** ✓（此前只在文档里记着落后 ✓）。

## Background（已确认的事实，2026-10-03 实测）

- **五个宿主包的最新版都是 1.0.0** ✓：`pi-agent-core` ✓ · `pi-coding-agent` ✓ · `pi-tui` ✓ · `pi-ai` ✓ · `pi-telemetry` ✓（registry 可达 ✓，`npm view` 退出码 0 ✓）。
- **本仓现钉 0.84.3** ✓：`pi-coding-agent` 与 `pi-tui` **精确** ✓、`pi-agent-core` `^0.84.3` ✓；本机实装也是 0.84.3 ✓（无漂移 ✓）。
- **`pi-agent-core@1.0.0` 的约束与依赖** ✓：`engines: node >=22.19.0` ✓（与本仓一致 ✓，**不新增约束** ✓）；`typebox 1.3.27` ✓；`pi-ai ^1.0.0` ✓ —— 而 adapter **直接依赖 `pi-ai` 的 `Api`/`Model`** ✓，所以**两个包同时跨主版本** ✗。

## Requirements

- **R1 只升级、先单独提交** ✓：五个包 → 1.0.0 ✓，然后**三连门禁** ✓；**该提交里不夹带任何修复** ✗（否则"红"不再是干净读数 ✓）。
- **R2 红的清单要完整** ✓：**编译期** ✓ / **运行期** ✓（事件名、命令注册、行为 ✓）/ **测试夹具** ✓ 三类分开 ✓，每条带 `file:line` ✓；**"没红但可疑"的也要列** ✓（尤其那句沉默点 ✓）。
- **R3 只修真的坏了的** ✓；**修不动的 → 在原位记为限制并降级该点** ✗（不是整个任务 ✓）。
- **R4 真的启动一次** ✓：把扩展装/加载进 Pi 1.0 ✓（本仓路径 ✓）→ **以真实输出为证** ✓，不是"应该能加载" ✗。
- **R5 三个已发布模式各走一遍** ✓（`code-audit` / `pentest` / `trading` ✓），其中**至少一次被拒** ✓。
- **R6 `--version` 必须真的报 1.0.0** ✓ —— 这是"升上去了"的**唯一**判据 ✓（`npm run pi:smoke` 覆盖 ✓）。
- **R7 收尾** ✓：全范围 `trellis-check` ✓ + 三连门禁 ✓ + 修不动的各自开任务 ✓。
