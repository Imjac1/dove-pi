# A1 设计：新仓结构、loop 接口、迁移机制

## 边界

本任务建**新仓库**（用户 2026-09-30 决定）并放入 axi 的最小骨架。**不改 dove-pi 的产品代码**；dove-pi 只是模块与测试的来源。

## 决策 1：迁移 69 个基座无关模块的方式 → **复制 + 记录来源提交 + 重设基线**

| 方案 | 反对理由 |
|---|---|
| submodule | 保留上游耦合，而 §2.5 的重写清单（loop、闸门、trace 通道）**就是要让它们分叉**——机制与设计互相打架 |
| subtree | 带进我们不需要的历史，且合并语义会让后续 `git revert` 变复杂（A1 的 AC-2 依赖干净的 revert） |
| **复制（选定）** | 代价是丢历史；用**记录来源提交 hash** 补回可追溯性。分叉是**有意**的，机制应当配合分叉 |

**落地**：在新仓的 `MIGRATION.md` 里逐项列出「模块 → 来源路径 → 来源提交 → 迁移时做的改动」，并写清哪些模块**按原样**复制、哪些**要改**（三个重写项）。

## 决策 2：`AgentLoop` 接口形态

最小 turn 接口，且**闸门是 loop 的一环**，不是宿主的扩展点——这是 §1.1 的直接推论（接在宿主扩展点上的强制，形态上就是 88/120 那一档）。

```
runTurn(input) -> { events, result }
  ├─ 组装上下文
  ├─ 模型产出工具调用意图
  ├─ gate(调用) ──► pass / remediate / refuse      ← 闸门在这里，loop 内部
  ├─ 执行（经隔离层，A2）
  ├─ 记录事件（经 A3 的通道）
  └─ 产出结果
```

适配器（`pi-agent-core` 的 thin `Agent`）**只负责模型调用与工具执行**，闸门与记录**不在适配器里**。这是"反悔成本 = 一个适配器"的具体含义。

## 组件挂载点

七个组件各一个**固定文件位置**，且必须**可被程序化修改**——语料对该类基座的硬要求是 *"General extensibility alone is insufficient."* 挂载点的清单与 AHE 的七子系统对齐，便于与语料对话。

## 提交与回退形态

- **一次逻辑改动 = 一次提交**；`git revert` 是唯一回退路径（不引入第二套机制）。
- `git revert` 必须能干净回退**两次连续**的改动（A1 的 AC-2 要演练）。

## "门禁等价"的定义（AC-4 的关键）

新仓的"等价"**不是**"跑得起来"，而是：**同一套测试跑在迁移后的模块上，得到与 dove-pi 相同的数字**（`typecheck` 干净、`test` 816/814/0/2、`test:installer` 141）。差异必须逐条解释，不能笼统声明。

## 风险

- **基线漂移**：迁移时顺手"顺手修一下"，数字就会变而说不清原因 → 复制阶段**只许原样**，改动必须单独提交。
- **`test:installer` 的前提**：该套件可能依赖 dove-pi 的打包/安装路径；若新仓结构不同，要按"同一断言、换路径"处理，并把这个差异写进 `MIGRATION.md`。
