# A2 执行清单

**测试先行**：本仓库的规矩是每个修复都要有一条"在改前会红的断言"。本任务的四条验收**先写成红测试，再实现**。

## 顺序

1. [ ] **写红测试（四条，全部先红）**
   - [ ] 编码规避：把被禁命令编码后再调用 → 必须被拦
   - [ ] 跨调用拆分：把同一操作拆到多次调用 → 必须被拦
   - [ ] 重试到历史淘汰：让相关上下文被压缩后再试 → 必须被拦
   - [ ] 保持性：把一条声明的消费端拆掉 → 传感器必须报警
2. [ ] **写故障注入**：逐条打断契约，确认对应校验器报警（照参考实现的 `eval:fault-injection`）。
3. [ ] **部件 ① 语法解析**：子命令识别 + arity/子命令表。
4. [ ] **部件 ② 策略判定**：声明式规则 + 状态机。
5. [ ] **部件 ③ 状态载体**：session-scoped，与消息历史分离；写一条"压缩后状态不变"的测试。
6. [ ] **部件 ④ 保持性传感器**：声明 → 消费端登记 → 回合末检查。
7. [ ] **部件 ⑤ 隔离**：Windows 走 Job Objects（依赖 A0.2）；做不到就**写下"我们没有 OS 隔离"**。
8. [ ] **补救**：每条检测器一个 `remediate` 分支；补救产物再走一次检测。
9. [ ] **AC-4 测试**：每条检测器触发后，回合**仍产出合法产物**。

## 验证

- 四条红测试全部转绿
- 故障注入：每条契约被打破时**对应**校验器报警（并验证对应关系，不是"有个校验器报警就算过"）
- AC-4：逐条检测器触发，回合仍产出合法产物
- `npm run typecheck` / `npm test`（数字不下降）

## 风险点与回退

- **风险**：状态进了上下文 → "重试到历史淘汰"那条测试会漏。回退：把状态移到 loop 状态，重新跑该测试。
- **风险**：补救产出违规 → 补救后再检测这条若省略，A2 会退化成外挂层。回退：补上二次检测。
- **风险**：隔离做不到却声称做到了 → 这是语料里唯一不存在的立场。回退：删掉声明，写下真实能力。
- **回退点**：部件 ⑤（隔离）与其余四部件**解耦**；隔离失败不阻塞其余四部件的交付。
