# Definitively usable: the requirement set, the task map, and what only this task can decide

## Goal

把"可以使用"从**一种说法**变成**一份带读数的结论** ✓ —— 结论要能指给一组可复算的读数 ✓，而不是指给一次记忆 ✓。

**本任务是父任务** ✓：它拥有**需求集** ✓、**任务图** ✓、**跨子任务的验收** ✓、以及**最终集成复盘** ✓；三个可独立规划/实施/检查/归档的交付物在子任务里 ✓。**本任务不是实施对象** ✗（它没有自己的产品代码 ✓）。

|---|---|---|
| `10-16-release-024` | 把 master 上四笔产品代码发成 **0.2.4** ✓ 并核对用户 URL ✓ | 发布作业绿 ✓、Latest ✓、四产物 ✓、URL 可取 ✓ |

**顺序（操作者 2026-10-16 定）** ✓：**发布 → 门 → 读数** ✓。依赖写在各自 prd/implement 里 ✓，**不靠树形位置暗示** ✓。

**顺序的后果，明写在 design 里** ✓：发布排在最前 ✓ ⇒ 那次发布是**由一个还可能在慢机器上无关变红的门认证的** ✓ —— 因而若 CI 因围栏而红 ✗，**不挪 tag** ✓：记录它 ✓，由门那个子任务修 ✓，发布照旧成立或被下一次取代 ✓。

## Requirements（跨子任务的需求集）

- **R1 门可信** ✓：仓库跑的验证不得依赖挂钟运气 ✓ ⇒ 那两处围栏改成**持有状态** ✓，并对同类配执行器 ✓。
- **R2 读数取在要发的构建上** ✓：先装当前树 ✓ 并**读回它自称是什么** ✓（实测 2026-10-16：托管安装现在报 `Dove Pi 0.2.1` ✗ ⇒ 这一步是承重的 ✓）。
- **R3 结论覆盖两个项目与两种模式** ✓：原判分克隆（Python ✓、`code-development` ✓ 可写 ✓）+ 第二个项目（不同生态 ✓、一个**不可写**模式 ✓）—— 覆盖面是**形状与模式轴** ✓，不是规模 ✗。
- **R4 判据可观测且不可自欺** ✓：可写那一遍看"活做成了" ✓（项目自己的测试从红到绿 ✓ + held-out 仪器字节未变 ✓ + 源克隆字节未动 ✓）；不可写那一遍**不期待绿** ✓，看的是**它如实拒绝/如实报告** ✓。
- **R5 边界照旧明说** ✓：结论的范围就是测过的范围 ✓。
- **R6 发布物含读数所说的一切** ✓；发布**不可回滚** ⇒ `release:check` 在 tag 存在之前跑 ✓。

## Acceptance Criteria

**这些是跨子任务的判据，只有父任务能判** ✓（每个子任务自己的判据在它自己的 prd 里 ✓）。

- [ ] 三个子任务各自归档，且各自的 prd 判据**全部勾上** ✓。
- [ ] **0.2.4 是 Latest** ✓，且用户 URL 实际取到的是它 ✓（这一条**不可能**由本地重演代替 ✓）。
- [ ] **两处围栏的变异结果**都记录在案 ✓：改坏行为则用例变红 ✓ —— 记录里能看到**红的样子** ✓，不只是一句"已修" ✓。
- [ ] **两个项目的读数**都在，且每个都带上：项目自己的测试结果 ✓、held-out 仪器字节 ✓、源/夹具未被改动 ✓。
- [ ] **临时安装与临时副本都已清掉** ✓（判分克隆回到三个字节钉子的状态 ✓）。
- [ ] 结论段落**逐条列出边界** ✓（R5 ✓）：两个项目 ✓、两种模式 ✓、收尾发生在下一次请求 ✓、驱动不回答交互问题 ✓、一遍就是一个样本 ✓。

## Out of Scope

- **第三个项目、第三种模式** ✗ —— 两个的边际价值已经很小 ✓，三个不会改变结论 ✓。
- **交互面（批准 / 对话框 / 问答）** ✗ —— 驱动器不回答问题 ✓，要看那块得先让它读屏按键 ✓，是另一片 ✓。
- **"一次请求里做完收尾"** ✗ —— 产品决定 ✓，这里只如实记录 ✓。
- **与 `10-03-ten-million-token-project` 的重叠** ✓ —— 那个任务的地盘是**规模**（~10M tokens ✓、长流程 ✓、压缩与连续性 ✓）；这里是**形状与模式轴** ✓（换生态 ✓、换模式 ✓）。两者都保留 ✓，**不合并** ✓，各自在自己的 prd 里写明与对方的分界 ✓。
- **旧版本回填** ✗。
