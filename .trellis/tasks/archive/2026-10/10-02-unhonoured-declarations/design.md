## 一个关键判断：**注释里的行号注定会烂** ✗

`scripts/mode-behaviour-map.mts` 的两处引用在**本任务之前就已经是错的** ✗（原文 `588`/`727` ✗，上一任务落地时实测 `704`/`847` ✗），而**两道门都看不见它** ✓。这里有两层问题 ✓，要分开修 ✓：

1. **引用本身** ✗ → **不再写行号** ✓：注释只点**函数名** ✓（`evaluatePermission` ✓）。行号在**注释**里没有任何读者会去校对 ✓，而它每次改文件都会烂 ✗ —— 规格页带行号是对的 ✓（那里有门 ✓），注释里带行号不是 ✓。
2. **无人看守的文件** ✗ → 把引用检查扩到 `scripts/**` ✓（**只查路径能解析** ✓，不要求行号 ✓ —— 与上面同一条理由 ✓）。

**这不是把门放宽，而是把一种注定会烂的引用从仓库里去掉** ✓；剩下的引用（路径 ✓）由门守 ✓。

## 数据流（R1）

```
调用意图 → 策略解析出这次调用的目标（与 conformance 门同一个 targetArgument ✓）
        → 模式声明的 exclusions 里若有它 → block（带补救 ✓）
        → 否则照旧
```
**排除项按目标 id 匹配 ✓**（两个模式里的 `t-payments`、`production-venue` ✓ 都是 id 形态 ✓）；地址也一并匹配 ✓，因为文档里的 target 两者都有 ✓。**方向是保守的** ✓：多匹配一次会拦住本该放行的调用 ✓，少匹配会放行本该拦住的 ✓ —— 所以 id 与地址都查 ✓。
