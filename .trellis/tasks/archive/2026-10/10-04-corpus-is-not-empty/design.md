# 设计：让"没有失败"这句话**说它自己在说什么**

## 边界（由两次推翻重新划定 ✓✓）

**不造**：新的采集 ✗ · 新的挖掘器 ✗（`summarizeCorpus` 已经在做，且做得比原计划好 ✓✓）· 新的 CLI 命令 ✗（面已量到 ✓）。
**要改**：**一句**注记 ✓ · **一处接线** ✓ · **三处命名** ✓。

## 病根（一句话 ✓✓）

`harness-corpus.ts:53` 的 `EMPTY_FAILURE_NOTE` 是一句**关于世界的断言**（*"the paths that produce one … are not preserved"* ✗），写在一处**只能断言输入**的地方（这个函数**只看得见调用方交给它的账本** ✓✓ —— 它自己的文档就写着 *"every ledger **the caller hands over** is counted"* ✓）。

→ 而实测：**那句话对真实会话是假的** ✗✓（13 个真实账本里有 3 个失败 ✓✓）。

## 修法（改**断言的范围**，不改**断言的用词风格** ✓）

**契约 1** ✓：**没有失败时，注记必须同时给出它据以判断的输入规模** ✓✓（"13 个账本 / 59 个请求里没有失败记录" ✓）—— 这把它从**世界断言**降回**输入断言** ✓。
**契约 2** ✓：**原因若要说，必须是这个函数能看见的事** ✓✓ —— host 测试不保留状态**是**件真事 ✓，但它是**另一条路径**的事实 ✗，所以要**分开写**（并且**标出它是另一条路径** ✓），不能拿它当"语料无失败"的通用解释 ✗。
**契约 3** ✓：`failures` 非空时**绝不出现**该注记 ✓（现状即如此 ✓，写成用例防退化 ✓）。

## 数据流（不变 ✓）

```
账本[] → summarizeCorpus → { terminals, refusals, failures[], 组件归属, cite, preserve, 注记 }
                                       ↑ 已经全部存在 ✓✓（实测输出见 prd ✓）
```

## 取舍与回退

- **取舍** ✓：注记**变长**（带上规模与路径说明 ✓）—— 代价是啰嗦 ✓；回报是**它不再说假话** ✓✓，而这是本会话反复确认过的那类错里最贵的一种（**让读者停止寻找** ✗）。
- **风险** ✗：注释/文案类改动**容易退化成"抄一遍事实"** ✗ → 由契约 1/3 的**两条用例**压住 ✓（一条查范围与规模 ✓，一条查非空时不出现 ✓）。
- **回退** ✓：单点文案 + 一处接线 ✓，回退面极小 ✓。
