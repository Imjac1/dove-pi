# 清理执行清单

**每一步一次提交，且先跑门禁。** 删除是**不可逆**的目录操作，所以顺序里内建了两个回滚点：先重指向再删 `plan.md`；先归档并提交再删备份。

## 第 1 步：收敛计划正本（先证后删）

**1a. 先证明"v7 `plan.md` 已被 `plan-v8.md` 取代"**——不能假设。
方法：把两份文档的**小节标题清单**抽出来逐条比对（`plan.md` 62.6 KB vs `plan-v8.md` 79.4 KB），列出：

- v8 里有的 §：✓ 取代
- **只在 v7 里有的 § 或段落**：这是判断点。若有 → 先把它们并入 v8（或保留 v7 并明确标注"部分被取代"），**不要**直接删。

**1b. 找出所有引用 `plan.md` 的地方**，逐条重指向 `plan-v8.md`：

- A0–A5 的 `prd.md` / `design.md` / `implement.md` / `readings.md` 里的"见 `plan.md` §X"；
- **`implement.jsonl` / `check.jsonl` 里的路径条目**——本项目自己记录过这个失败模式：归档会打断条目里的路径而**读起来还很正常**（`AGENTS.md` 那条 58/66 实测）。**jsonl 里的路径必须逐条核**。
- 提交（**第一次提交：只重指向，不删**）。判据：`grep -rn 'plan\.md' --include=*.md --include=*.jsonl .trellis` 的每一条都能解释。

**1c. 删 `plan.md`**（第二次提交）。判据：全仓 grep 不再有指向它的引用；门禁三条读数不降。

## 第 2 步：工具备份（先归档 → 提交 → 再删）

**2a. 与 git 历史比对，不是与现行工作树比。**
我先前就是比错的（"86/114 与现行文件逐字相同"只说明它没被改过，不说明它在 git 里）。正确做法：对两份备份的每个文件，在**全部 revision**里找同路径同内容的 blob（`git rev-list --all -- <path>` + `git cat-file`）；**找不到的**才是"只存在于备份里的内容"。

**2b. 把只存在于备份里的内容打成一个归档**，放进本任务目录，随附**哈希清单**（路径 + SHA-256 + 原备份名），然后提交。

**2c. 删两个 `.trellis/.backup-2026-09-25T13-20-05` / `…-12` 目录**（第三次提交）。判据：归档在仓内且能列出；`git bundle`-式核对清单可用；`.trellis` 体量的前后读数在手。

## 风险与回滚点

| 风险 | 处理 |
|---|---|
| 删 `plan.md` 打断引用 | 1b/1c **分两次提交**；先重指向后删；提交本身是回滚点 |
| 备份里其实有 git 没有的内容 | 2a **与历史比**，不与管理树比；2b 归档 + 哈希清单先提交 |
| v7 里有 v8 缺失的段落 | 1a 的比对结果决定：**先并入再删**，或保留并标注 |
| 乱码修复反而弄坏 `task.json` | 改前留副本于提交历史；改后跑 `task.py list` 验证 |
| 误删记录类 | 本次范围**不含**归档任务、journal、读数、规格；一旦发现"待删项其实被引用"，**停下来报告**而不是硬删 |
