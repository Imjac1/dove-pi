# What the template hashes can and cannot say

## Goal

Say in the check that reads the tool own hash file what those hashes are, because a reader can reasonably conclude they prove the
tracked files are untouched - and they do not.

## Background: the measurement and its classification

Recomputing sha256 for all 181 tracked files:

```text
tracked: 181   unchanged: 73   CHANGED: 34   absent: 74
```

**Classified, the 34 and the 74 are almost entirely not about us**:

| Class | Examples | Who is responsible |
|---|---|---|
| tool files updated since init | `.trellis/scripts/task.py`, `common/*.py`, `.trellis/workflow.md`, two `.agents/skills` | a Trellis update, not a person |
| generated bytecode | `common/__pycache__/*.pyc`, both Python versions | CPython, on import |
| gitignored runtime state | `.trellis/.runtime/sessions/*.json` | the runtime, by design - `.trellis/.gitignore` lists `.runtime/` and `**/__pycache__/` |
| **edited by this repository, on purpose** | **`AGENTS.md`** | us, and a test holds its position outside the managed block |

**And the file itself says what it is**: `.trellis/.version` reads `0.6.16`, the hash file `__version` reads `2` - the baseline was
written when the project was initialised, and nothing rewrites it on a later update.

**Why this mattered for a moment**: the raw numbers read like "forty-four tool files were modified locally", and they are not. A check
that reads this file should carry the classification, so the next reader gets the number without the wrong conclusion.

## Requirements

- **R1 - The check that reads the hash file says what it is**: an init-time baseline of tool files, not a tamper check - and a
  difference there means a tool update, generated bytecode, or a repository edit, in that order of likelihood.
- **R2 - It keeps doing what it did**, which is to assert that no specification is tracked: the classification changes the comment, not
  the rule.
- **R3 - The classification is recorded** in the task, with the four rows and who is responsible for each.
- **R4 - No new check is added for the hashes themselves**, because the file cannot distinguish the three causes and a check that
  guessed would be wrong about two of them.
- **R5 - The gate passes**: typecheck, the suite, the installer tests, doctor and the spec budget test.

## Acceptance Criteria

- [ ] **AC1** The check comment states the baseline, the three causes, and the one file this repository edits on purpose.
- [ ] **AC2** The rule it enforces is unchanged, and the suite passes with the same counts.
- [ ] **AC3** The classification table is in the task.
- [ ] **AC4** The gate passes.

## Out of scope

- **A tamper check**, which this file cannot support.
- **Cleaning the bytecode or the runtime state**, which is gitignored and belongs to the tools.
- **The first real turn**, which needs a Pi host.
