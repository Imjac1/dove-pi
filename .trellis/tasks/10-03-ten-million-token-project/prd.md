# A ten-million-token project through the real flow

## Goal

**跑一个规模到 ~10M tokens 的"真实使用"过程** ✓，看**流程本身**在这个尺度上会怎样 ✓，并把过程中暴露的问题与可优化点整理出来 ✓。

## Background（已量，2026-10-03 ✓）

- **产品自己能量** ✓✓：`dove-pi token audit [--since=Nh]` ✓（`src/cli.ts:231` ✓）与 `dove-pi cache audit` ✓（`:251` ✓）。
- **今晚那场真实走查的用量** ✓：1 个项目 ✓ · **1 个会话** ✓ · **43 条消息** ✓ · **prompt 832,064** ✓ · output 11,841 ✓ · reasoning 3,863（占 output **32.6%** ✓）✓。
- **换算** ✓：**~19K prompt / 消息** ✓ → **10M ≈ 520 条消息 ≈ 今晚的 12 倍** ✓✓。
- **✗ 第一条实测到的优化点**：那 43 个请求里 **42 个全 MISS** ✓（累计命中 **0.0%** ✓ · 热态 **0.0%** ✓ · 未缓存 input = 832,064 = 全部 ✓）→ 策略列 `no-context` ✓（"未额外注入快照、最小前缀路径" ✓）→ 提供商侧归因写着"**提供商未命中或缓存过期**" ✓。**即：10M 会按全价 input 付** ✗✓。
- **运行时不记录 token** ✗✓（`src/` 里没有 usage/token 字段 ✓）→ 尺度只能靠 `token audit` ✓（它读的是**宿主的**记录 ✓）。
- **宿主自己的账本** ✓：`%USERPROFILE%\.pi\agent\dove\workspaces\<hash>\execution.jsonl` ✓ —— 今晚那份 **770,456 B** ✓（另两份 9 KB / 44 KB ✓）→ **10M 级会大约 10 倍于此** ✓✓。
- **已知的规模相关事实** ✓：宿主有**延续接口** ✓（`--continue`/`-c` ✓、`--session` ✓、`--session-id` ✓、`--resume` ✓）；上一轮实测**一次 `--continue` 回合跑了 21 分钟无输出** ✓ 而它的任务文件 `updatedAt` 显示**一直在干活** ✓（**原因未定位** ✗）；真 provider 已 `ready` ✓；**存在速率上限（历史 R2）** ✓。
