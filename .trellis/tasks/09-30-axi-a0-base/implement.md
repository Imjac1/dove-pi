## 风险点

- **A0.1 的弹窗**：`workspace-write` 带 `approval: ask`，**弹窗不算失败**；不要把它读成拦截。
- **A0.1 的误读**：界内写失败（例如路径写错）会让你以为越界也被拦——**必须同时做界内对照**。
- **A0.2 的过度约束**：Job Object 配得太严会把子进程打死，那**不算通过**；判据 2 就是防这个。
- **A0.2 的假通过**：只在"写失败"时报错、却没验证"目标树确实不可写"（例如进程根本没起来）——要用**可观测的写入尝试日志**。
  **已发生两次同类错误，补两条**：
  - **进程没起来**：用 `pwsh` 起子进程，而本机 PATH 上没有 `pwsh` → 子进程未执行，"文件不存在"被误读成"被挡住"。**起子进程要用 PATH 上确有的东西（`cmd.exe`），并加基线对照。**
  - **错误码取值不即时**：把 `GetLastWin32Error()` 包进 PowerShell 函数 → 拿到陈旧的 203，而真实结果是 **True / 0**。**P/Invoke 的错误码必须在紧邻下一句取，不得经过任何函数或其它调用。**
- **A0.2 后半的三条仪器风险（新增）**：
  - **限制列表可能是空的**：`CreateRestrictedToken` 返回成功不代表限制生效——必须 `GetTokenInformation(TokenRestrictedSids)` **读回**；空列表读成"拦住了"就是第四次同类错误。
  - **受限进程可能根本起不来**：限制 SID 会挡住系统 DLL 的加载（那些授予给 `Everyone` / `Users`）→ 每次都要基线对照 + 子进程自己的输出行。
  - **属主隐含的 DACL 写权限**可能让"摘不掉"不成立 → 判据 2 必须真的执行，不能按 ACL 常识推断。
- **A0.3 的滑坡**：把"提示词档提醒"读成"机制级实现"。判据是**拦截发生在模型之外**，还是模型选择不删。
