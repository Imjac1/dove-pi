# First contact: what a real user's first run does

## Goal

让**终端用户装完第一次使用**这条路被**一遍走完** ✓ —— 全新安装 → 三个已发布模式各自加载 → 各跑一个真实回合（**含被拒的那一个**）→ 用户**看到什么** → 账本对不看代码的人是否可读 → 升级 —— 并让**它撞出来的东西**变成任务 ✓。

**用户价值** ✓：这条路径上**已经出过两次阻断级缺陷** ✓（`modes/pentest` 的窗口到期 ✗、`modes/trading` 的 `exclusions` 从写下那天起就拦不住 ✗ 而它**自我声称**拦得住 ✓），两次都**不是**被测试发现的 ✓。场景把"发现它们的成本"从**偶然**降为**一次运行** ✓。

## Background（已确认的事实，本会话量到）

- 现有"真实路径"覆盖只有三样 ✓：`real-dove-blackbox`（**20 条** ✓，真实启动器 + 确定性 provider ✓）· `interop-smoke-matrix`（**1 条** ✓）· `managed-install-status`（**1 条** ✓），加上 installer 的 **141 条** ✓ —— **都不到"第一次接触"** ✗。
- **端到端一格空着** ✗：全新安装 → 三个模式 → 一个回合 → 用户所见 → 账本 → 升级，从没有一遍连起来跑过 ✓。
- 本会话另有一条**同类**证据 ✓：`axi-turn` **装完跑不到** ✗（不在启动器的路由表里 ✓）—— 这类"装好了但用不了"的缺陷**只有走一遍才会撞到** ✓。
- 场景的**产出是缺陷清单** ✓：撞出东西**就是它成功** ✓，不是它的失败 ✓。

## Requirements

- **R1 私有根** ✓：整条路径在**私有的 `DOVE_PI_HOME`** 下跑 ✓（本仓已有这个先例 ✓：`managed-install-status` 用它 ✓），**绝不**碰用户真实安装目录 ✗ —— 一次真安装的副作用必须在私有的地方 ✓。
- **R2 全新安装** ✓：从干净状态装一遍 ✓，并留下"装完了"的可核读数 ✓。
- **R3 三个已发布模式各自加载** ✓：`code-audit` / `pentest` / `trading` ✓ —— 读数含 **id、版本、以及它们的声明** ✓（本会话的两次缺陷都在**声明**上 ✓）。
- **R4 每个模式一个真实回合** ✓，其中**至少一次是被拒的** ✓ —— 读数：用户**看到的文案**是否点名**原因**与**出路** ✓（"拒绝了但没人知道为什么"是本仓反复出现的同族 ✓）。
- **R5 账本对人是可读的** ✓：一个**不看代码**的人能否说出"刚才发生了什么" ✓（可测的近似：每条拒绝都能被解释 ✓）。
- **R6 发现路径** ✓：命令可发现性 ✓（`--help` / 启动器路由 ✓）—— 直接对应上面那条 `axi-turn` 缺陷 ✓。
- **R7 升级** ✓：第二次安装**不破坏**既有状态 ✓（最后一步；若无法便宜自动化 → 如实记为限制 ✗）。
- **R8 形态是测试** ✓，一次人工过场不算 ✓（不成套的场景会烂 ✓，与本仓引用同理 ✓）。撞出的红**必须变成任务** ✓，不许静默跳过 ✗。

## Acceptance Criteria

- **AC-1** 全新安装在一个私有 `DOVE_PI_HOME` 下**跑完** ✓，且**用户的真实安装目录在前后完全未变** ✓（可观察：前后各量一次 ✓）。→ R1、R2 ✓
- **AC-2** 三个已发布模式**各自加载成功** ✓，并报出各自的 **id 与版本** ✓。→ R3 ✓
- **AC-3** 每个模式**至少一个回合真的执行** ✓（不是"加载成功"就算 ✓）。→ R4 ✓
- **AC-4** 至少一次**被拒** ✓，且用户看到的文案**同时含原因与出路** ✓。→ R4 ✓
- **AC-5** 账本里**每条拒绝都会被解释** ✓（名字 + 原因 ✓）。→ R5 ✓
- **AC-6** `--help` / 启动器能把用户带到 `axi-turn`**这一类入口** ✓（本会话那条缺陷的直接回归测试 ✓）。→ R6 ✓
- **AC-7** 第二次安装后**状态仍可用** ✓（模式仍能加载 + 账本仍在 ✓）。→ R7 ✓
- **AC-8** 门禁**不下降** ✓（typecheck 0 / `npm test` 0 fail / installer OK ✓）。→ R8 ✓

## Out of Scope

- **对抗者场景** ✗（伪造工具调用 ✓、删 trace ✓、放宽沙箱 ✓）—— 那是 **A3** 的题目 ✓；**真实用户永远不会做那些事** ✓，而项目的命题正是关于那些事的 ✓。
- **改进回路**（Plane C ✓）✗ —— 依赖 A2 的传感器与 A3 的通道 ✓，两者都还没建 ✓；A3 落地后可作为它的对手场景补上 ✓。
- 真 RSI ✗、评测接入 ✗（A4/A5 ✓）。
- 跨平台 ✓（本场景在**这台机器**上跑 ✓；其他平台另说 ✓）。
