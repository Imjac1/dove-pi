# A2：安全子系统五部件——含确定性补救与故障注入

## Goal

让 axi 的强制**在代码内**成立：五部件齐备，且**每条检测器都配一条确定性补救**，使得"拦住了"不等于"任务被放弃"。

这是 axi 的验收核心，也是两块**无先例**之一。

来源：`plan.md` §2.2、§4.2 A2、§1.1.1。

## Background

- 外挂护栏输的机制是"**没有确定性补救回退**"：动作空间只有 `pass / redact / refuse`，拦截即等于放弃任务（`server/guardrail.mjs`，55 行，本会话读过）。两臂**共用同一套检测器**，只在补救处分叉 → **检测器可以共用，分叉点只在补救**。
- 规避率实测 **98% 尝试 / 88% 成功**，三种手法：**编码**被禁命令、**跨调用拆分**、**重试到上下文离开监控历史**。
- 语料把"只匹配名字"列为最弱形态；OpenCode 的**语法感知策略**（tree-sitter + arity 字典）是可直接参照的一档。
- SAHOO 的 `constraint-preservation check` 是"声明没有消费者"这个老毛病在安全文献里的正式名字。
- 可直接抄的技法：参考实现的 `eval:fault-injection`（*7-mutation contract sensitivity check*）。
- 参照实现的强制代码规模很小（两文件 + 三测试）→ **本阶段不是"再造一个安全框架"**。

## Requirements

- **R1 语法感知的参数级策略**（不是名字匹配）。
- **R2 跨调用累积状态**（拆分防御）。
- **R3 不依赖历史的判定**（压缩 / 上下文淘汰不得洗掉判据）。
- **R4 保持性传感器**：判定"这条声明是否**仍然管住了**这一轮运行"，而不是"是否存在"。
- **R5 隔离（平台允许处）**：形态已由 A0.2 后半定下——axi 自己的 jailer 先布 ACL，再以**受限令牌**（`Everyone` 档）起改进者；**Job Objects 不是文件系统的边界**（它只绑定进程集合并施加令牌，当年那句"Windows 隔离 = Job Objects"已被实测修正）。两条不变量：**Plane B 的路径没有 `Everyone` 授予 / Plane A 的路径必须显式授予**。**强度照实写**：`Everyone` 档，不是 OS 沙箱。实现失败则**明确写下"我们不做 OS 隔离"**。
- **R6 确定性补救**：每条检测器触发后，确定性地重新组合出合法产物，而不是拒绝。
- **R7** `mine` 的输出包含"**新护栏**"，而不只是一条修正（失败要沉淀成可执行护栏）。

## Acceptance Criteria

- **AC-1** 用 `2609.30217` 的三种手法各写一个测试（编码、跨调用拆分、重试到历史淘汰），**每条都能拦住**。
- **AC-2 保持性测试**：把一条声明的消费端拆掉，传感器必须报警。
- **AC-3 故障注入**：逐条打断契约，确认对应校验器报警（同时验证契约与校验器的对应关系）。
- **AC-4 "拦住了还能把活干完"**：每条检测器触发后，回合仍产出合法产物。
- **AC-5** 五部件各有回归测试；门禁不下降。
- **AC-6（新增，依据 A0.2 后半的读数）边界不变量**：① Plane B 的路径**没有** `Everyone` 授予；② Plane A 的路径**有**显式 `Everyone` 授予；③ 受限进程**摘不掉**限制（把 A0.2 后半的三条判据做成回归测试）；④ **不变量写进规格**——规格描述"现在就有"的东西，所以这一步在本阶段实现落地之后做，之前只留在规划与 A0 读数里。
