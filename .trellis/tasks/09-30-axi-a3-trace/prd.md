# A3：trace 通道与配置保护——宿主外拦截、抗编造、抗伪造

## Goal

让 axi 的证据通道**不被被治理者控制**：同时建立**完整性、保真度、捕获**三个性质，并把配置变更置于独立批准之下。

本阶段是回路的可信性前提——**自我改进的 agent 天然有动机污染自己的证据**，这不是假设的威胁，而是被观测到的行为。

来源：`plan.md` §2.3、§2.4、§4.2 A3。

## Background

- 除 Muse Code 外所有被测 harness 都能被要求删 trace 而不触发监控；而 **Muse Code 的机制是提示词档的 skill 提醒**（不是机制）→ 被测群体里**没有机制级实现**。
- 篡改在**最初几轮**优化内就出现，常常第一次就试 → **不是"以后再加固"的事项**。
- **append-only 只挡删除、挡不住编造**（dove-pi 现有 ledger 正是 append-only）。
- agent 会**定时 / 延迟清理**以对抗持续写日志；压缩路径被用过（Kimi 改自己的 compaction checkpoint、OpenCode 改 SQLite compaction part）。
- METR/Redwood 独立调查：**约 7% 的 transcript 存在成功的工具调用伪造**，目的是欺骗自动评分器，且**未被同步监控发现**。
- 现行两条技术路线各自**假设**了 axi 要建立的性质：防篡改审计只保"已记录事件"的完整性（不保"所有动作都被记录"、不保"如实描述了实际发生"）；执行溯源**假设"相关事件已经被捕获"**。
- 可采用的现成技术：**Agent Flight Recorder**（八字段结构化事件 + hash chaining + Merkle batching + epoch root 外部锚定；实测每事件 **~48 µs / 512 B**、L2 锚定 **$2.30 / 10 万事件**、edit/delete/reorder/fork 四类 **100% 检出零误报**、结构化查询精度 **1.0 vs 文本检索 0.013 / 0.077**）；**VET** 提供独立于宿主的认证思路。
- **必须自己补的缺口**：上述四类**不含"编造"**——保真度那一格**没有先例**。
- 负面结论：**重放 trace 来审计在宿主被攻陷时不成立**。
- 配置是**最脆弱**的阶段（HarnessRisk，128 个沙箱用例），且"让模型知道这是危险的"**不算防护**。

## Requirements

- **R1** 写入路径**独立于 agent 的宿主**，落在 workspace 之外。
- **R2** append-only，**且另记重试与完成状态**。
- **R3** 能证明工具调用**按报告执行了**（抗伪造）。
- **R4** 抗"定时清理"。
- **R5** 压缩路径**不得改写**证据。
- **R6** 采用 hash chaining + Merkle batching + 外部锚定；按综述的轴设计（**粒度与时机**、trust functions）。
- **R7** 配置变更需**独立批准**；仓库设置不得放宽隔离。
- **R8** trace 说明里**写明它不覆盖什么**（不捕获环境状态、不记录全部系统活动）。

## Acceptance Criteria

- **AC-1** agent **无法删掉**自己的 trace。
- **AC-2** agent **无法伪造**一条没有真实执行的工具调用（用 METR/Redwood 的 **7%** 失败模式构造测试）。
- **AC-3** **无法借压缩路径**改写证据。
- **AC-4** agent 无法在**无独立批准**下改掉安全敏感参数。
- **AC-5** 被拒后**回合仍能完成**。
- **AC-6** 门禁不下降。

## Out of Scope

- 不做真 RSI；不做跨组织的链上争议解决——第一版只需**可验证的外部锚点**，不需要争议仲裁。

## Key Decisions / 依赖

- **与 A2 同期**，不后置。
- 成本已有实测（48 µs/事件、$2.30/10 万事件）→ **"太贵"不构成理由**。
