# Design

## 边界：这一轮动什么、不动什么

**动** ✓：`src/core/work-mode.ts` 的**根解析** ✓ · 扩展的状态行进入读数 ✓ · 运行器脚本**只在必要时** ✓。
**不动** ✗：`summary` 的资源块 ✗ · 退出码成因 ✗（都归 `10-05-divergent-records-unreconciled` ✓）· 任何**已归档**的读数 ✗（只在其上追加更正 ✓）· **`cachecontrol` 项目** ✓（它是被测项目，不是本仓的代码 ✓）。

## 缺口 ①：一个被声明的 mode 加载不了 —— **选"相对扩展解析"** ✓✓

**已量的事实** ✓✓：

| 事实 | 出处 |
|---|---|
| 项目级声明是 `.dove/mode.json` ✓ | `src/core/work-mode.ts:879` ✓ |
| 优先级：**显式覆盖 > 项目声明 > 一条蕴含** ✓ | `work-mode.ts:903` 的文档 ✓ |
| 声明被**读到**（拒绝信息里有它的名字 ✓） | 运行记录 `flow-mode.jsonl` 的扩展状态行 ✓✓ |
| 失败是 `missing-file` ✗ | 同上 ✓ |
| mode 从 **`<root>/modes/<name>/`** 载入 ✓ | `work-mode.ts:996` ✓ |
| 运行时的工作目录 = **项目** ✗ | `scripts/real-dove-blackbox.mjs:110-111`（`spawn(…, {cwd: workspaceRoot})`）✓ |
| 覆盖来自**环境变量** `DOVE_PI_WORKSPACE_MODE_OVERRIDE` ✓ | `src/pi-adapter/extension.ts:694` ✓ |
| runner **从不设置**那个变量 ✓ | 同文件 `:112-117` 的 env 块 ✓ |
| `--mode rpc` 是**传输**参数 ✓ | `real-dove-blackbox.mjs:101-103` ✓ |
| 工作模式开关是 **`--workspace-mode=`** ✓ | `dove_pi.py:124` ✓ |

**选定的修法** ✓✓：**mode 目录相对*扩展*解析** ✓ —— 即 `<root>` 不再等于"工作目录"，而是**扩展自己能定位到的目录** ✓。**理由** ✓：① **它修的是所有布局** ✓（不止这一种 ✓）；② **它落在本仓自己的代码里** ✓，不在运行器脚本里 ✓；③ **它让"用户在项目里声明 mode"这件事成立** ✓✓ = **用户不能自救的那个缺口** ✓。
**保底第二手** ✓：**拒绝时把"我找过哪里"写进拒绝文本** ✓✓ —— 便宜 ✓，且让下一次的读数**自带答案** ✓（今天我只能靠扩展的状态行反推 ✓）。

**已知风险** ✗✓：**本仓此刻有两个红的测试正压在这片区域** ✗✓✓——`cites the declaration each mount-point row names, as that page says it does` ✓ 与 `registers modes, shortcuts, capabilities, and doctor` ✓ —— **而且是一个并行窗口正在改的** ✓（当前 HEAD `c275554` 是它的 ✓· `935 / 931 pass / 2 fail` ✓）→ **本任务开工前必须先把那一处落定** ✓✓，否则**分不清是谁弄红的** ✗✓。

## 缺口 ②：宿主没有 hashline 编辑工具 —— **选"降级并记录"** ✓✓

**已量的事实** ✓✓：扩展**自己打印** *"当前 Pi 宿主未提供 hashline 编辑工具（replace<path> Pi 或执行 dove-pi install"* ✓✓（运行记录 `flow-mode.jsonl` 的 `extension_ui_request`/`notify` 条目 ✓）；**而会话照跑** ✗✓；**读数 #3 因此出现"改了一个文件、没修好目标、弄坏一条通过的用例"** ✗✓。

**选定的修法** ✓✓：**把这条事实从"一条通知"变成"读数的一个字段"** ✓✓ —— 与 mode 用**同一条通道**：扩展已经在打 `` `workMode=${activeWorkMode?.id ?? "none"}` `` ✓（`extension.ts:1172` ✓）→ **把工具面的状态并列打印** ✓（**在场** ✓ / **缺失且理由是宿主未提供** ✗✓）→ **并让 §4 的读数格式收下它** ✓。
**理由** ✓：**宿主是 Pi，不是本仓** ✗ → **修不到根上** ✗；**但"读数看得见"是本仓能给的** ✓✓，**而且它立刻让"模型草率"与"工具不在"在读数上可分** ✓✓ = **本轮最想要的那件事** ✓。

## 数据流与契约 ✓

```
一次运行
  → launcher: dove-pi（source: dove_pi.py）           ✓ 已成立
  → 扩展加载                                          ✓ 已成立
  → 模式解析：覆盖(env) → 项目声明(.dove/mode.json) → 蕴含   ✓ 已成立
  → 模式载入：<root>/modes/<name>/                     ✗ 今天 <root>=项目 ⇒ missing-file
  → 工具面：hashline 编辑工具在场?                     ✗ 今天只在 notify 里说
  → 会话 → 账本(事件流) + 会话记录 + summary
  → 判分：在运行器那份副本里跑项目自己的套件            ✓ 已成立
```

**契约** ✓✓：**判分不由 field run 给** ✗（§5 ✓）· **累计量数账本** ✓（`summary` 的资源块是单条记录 ✓）· **退出码不作判据** ✓（同一命令三种码 ✓）。

## 权衡与回滚 ✓

- **取舍** ✗：修 ① 碰**本仓受测面** ✓（有撞车风险 ✗✓）**换**"用户在项目里能声明 mode" ✓✓；② 只记不修 ✓ **换**读数可信 ✓✓ **而宿主缺口仍在** ✗。
- **回滚点** ✓✓：两处改动**各自可独立回滚** ✓（① 是 `work-mode.ts` 的根解析 ✓；② 是状态行 + 读数 ✓）—— **不共享一行** ✓。
- **不做的** ✗：**不在实验进行中改运行器** ✗（上一夜已量：会让依赖它的读数失去可比性 ✓）；**不改 Pi 宿主** ✗。
